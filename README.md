# Dark Vessel Inspection Triage

**NVIDIA Open Models Codefest 2026 — team submission**

An agentic decision-support system that turns open satellite radar detections into
prioritised, explainable inspection briefs for European fisheries control authorities.

## The problem

Illegal, unreported and unregulated (IUU) fishing is a major EU policy problem, and Spain
operates one of the largest fleets in the Union. Fishing vessels carry AIS transponders
that broadcast their position — but a transponder can be switched off. Research using
Copernicus Sentinel-1 radar found that a large majority of fishing vessels at sea are not
broadcasting their positions, and that these non-broadcasting vessels are more often
associated with illicit activity than those that do broadcast.

Inspectors cannot patrol the whole sea. They need to know **where to look**.

## What the system does

Given radar vessel detections for a sea area and the applicable regulatory layers, it:

1. Cross-references each detection against AIS matching, marine protected area
   boundaries, seasonal closures and permitted fishing gear.
2. Scores each detection with a **transparent, itemised breakdown** — no black box.
3. Reasons over the whole scene, prioritises inspection candidates and identifies spatial
   patterns.
4. Produces inspection briefs stating the indicators, the regulation concerned, the
   suggested action, and — critically — the innocent explanation that could account for
   the indicator.

## Duty of caution (core design decision)

**A vessel not broadcasting AIS is not automatically an offender.** Vessels below the legal
length threshold are not required to broadcast at all. The system marks these as
**non-assessable**, scores them zero, and never prioritises them — and it says so
explicitly in its output.

This is not a technical detail. It is what separates a legitimate triage tool from a
machine that accuses people without basis. The system speaks in terms of *indicators
justifying inspection*, never *offences*. A human always decides.

## Architecture

```
GFW / Sentinel-1 detections ─┐
Marine protected areas       ├─> deterministic cross-reference ─> analyst agent ─> writer agent ─> briefs
Seasonal closures            │        analisis.py                  Nemotron         Nemotron
Gear restrictions            ─┘   (auditable, no LLM)
```

Positions, geometry and scores are computed deterministically and are **never generated by
the model** — in an inspection file the figures must be auditable. The open models handle
interpretation, prioritisation and drafting, which is what they are good at.

**Open models:** NVIDIA Nemotron, served via NIM. Because the weights are open, the system
can run inside the authority's own environment and its reasoning can be audited — both
requirements when the output feeds an enforcement decision.

## Status

Working end-to-end prototype on synthetic detections whose schema deliberately mirrors the
real sources, so going live means changing only `datos.py`.

| Layer | Planned source |
|---|---|
| Vessel detections | Global Fishing Watch — "Vessel detections from Sentinel-1 SAR" |

## Running it

```bash
pip install -r requirements.txt
export NVIDIA_API_KEY='nvapi-...'      # from build.nvidia.com
python src/main.py

# Deterministic cross-reference only, no model calls:
python src/main.py --solo-cruce
```
